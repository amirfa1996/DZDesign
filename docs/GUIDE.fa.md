# راهنمای سادهٔ DZDesign

## از کجا شروع کنم؟
پس از نصب، پروژهٔ واقعی را در Codex باز کنید و درخواست روشن بدهید:

> با DZDesign کد فعلی را بررسی کن. برای صفحهٔ اصلی یک طرح فارسی و راست‌به‌چپ متناسب با مشتری پیشنهاد بده؛ بعد محلی اجرا و نسخهٔ موبایل را بررسی کن.

لازم نیست همهٔ مهارت‌ها را هم‌زمان فعال کنید. برای صفحهٔ جدید `dz-taste`، اصلاح صفحه `dz-polish`، تست `dz-browser`، مرجع مشخص `dz-library` و مدل سه‌بعدی `dz-three` مناسب است.

## سه مثال کاربردی
۱. «با dz-polish فرم ثبت سفارش را بررسی کن؛ پیام خطا، خوانایی و نمایش موبایل را درست کن.»
۲. «با dz-library مرجع Notion را بخوان و با رنگ و محتوای برند من یک پنل ساده طراحی کن.»
۳. «با dz-browser مسیر ورود تا ثبت فرم را روی لوکال تست کن و از نتیجه اسکرین‌شات بگیر.»

## چه چیزی تحویل بگیرم؟
کد و فایل‌های قابل‌بررسی، توضیح تغییرات، نتیجهٔ تست‌های اجراشده و مواردی که قابل‌آزمایش نبودند. «نصب شد» به معنی «همهٔ سناریوها آزمایش شدند» نیست.

## منابع و هزینه‌ها
منابع اصلی به‌صورت نسخهٔ ثابت از GitHub دریافت می‌شوند؛ هر پروژه پوشهٔ `.dzdesign` خودش را دارد. اولین دانلود ممکن است زمان ببرد. در صورت قطع شبکه، ابزار خطا می‌دهد و نباید ادعای موفقیت شود. هزینهٔ اشتراک Codex، API یا افزونه‌های اختیاری جزو این بسته نیست.

## خطاهای رایج
- Python یا Node پیدا نمی‌شود: نسخه و PATH را بررسی کنید؛ ابزار doctor را اجرا کنید.
- مرورگر بسته می‌شود: دسترسی محیط، نصب مرورگر و پیام خطا را بررسی کنید؛ حفاظت محیط را غیرفعال نکنید.
- مهارت دیده نمی‌شود: نصب و نسخهٔ Codex را بررسی کنید؛ در صورت نیاز برنامه را باز و بسته کنید.
- تفاوت checksum: دانلود اجرا نشود؛ فایل قفل را برای دورزدن خطا تغییر ندهید.
