# DZDesign / دیزاین دیجی‌زورگ
Read the user's project before proposing changes. Keep each client separate. Preserve the project's framework and established brand unless a redesign is requested. Respond in the user's language.

## Choose only the module needed
- New frontend / distinct visual direction: read `../dz-taste/SKILL.md`.
- Critique, accessibility, polish, or live variants: read `../dz-polish/SKILL.md`.
- Browser interactions and screenshots: read `../dz-browser/SKILL.md`.
- Named brand design reference: read `../dz-library/SKILL.md`.
- Reference photo to a procedural Three.js object: read `../dz-three/SKILL.md`.

Do not load every module or stack conflicting aesthetic rules. The user's brief and existing design system win. Build an agreed local result, inspect it at desktop and mobile sizes, and report what was actually tested. Publication is a separate action requiring user authorization. No ranking, conversion or income guarantees.
